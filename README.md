# BioSEM

## GitHub · Vercel 배포

사용자 요청으로 배포 대상을 Vercel로 변경했습니다. `vercel.json`에서 정적 결과 폴더를 `dist`로 지정했으므로 GitHub 저장소를 가져오면 별도 빌드 없이 배포하도록 준비되어 있습니다.

- 저장소 루트: 이 폴더
- Framework Preset: Other
- Output Directory: `dist`
- 별도 설치·빌드 명령 없음
- 실제 회원 로그인은 Supabase 연결 완료 전까지 비활성
- `.openai`, `.sites-runtime`, `.vercel`, 환경 비밀 파일은 GitHub 업로드에서 제외

현재 GitHub 저장소 생성과 Vercel 계정 연결을 기다리고 있습니다. 저장소 등록 또는 배포가 완료된 것으로 간주하면 안 됩니다.

## 프로젝트

생물교사 SEM 커뮤니티입니다. 승인된 디자인에 회원 승인 기능을 추가했으며, 실제 인증 계정과 데이터베이스 연결을 기다리고 있습니다.

## 미리보기

`dist/index.html`을 브라우저에서 직접 열 수 있습니다. 별도 설치 없이 모든 디자인 페이지와 갤러리, 안내 화면을 이용할 수 있습니다.

로컬 서버는 프로젝트 폴더에서 `node server.mjs`로 실행합니다. 주소는 `http://127.0.0.1:4310`입니다.

## 포함된 화면

- 홈, 소개 및 비전, 활동 기록, SEM 갤러리, 교육 자료, 구성원, 커뮤니티
- 활동 및 이미지 분류, 이미지 확대 및 출처, 활동 상세 보기
- 수업 기록지와 인쇄, 커뮤니티 공지와 회원 영역 안내
- 로그인, 가입 절차, 가입 신청 폼, 승인 대기 미리보기
- 내 계정 및 회원 상태, 운영진 신청 목록·검색·페이지 이동, 승인·반려·정지·복구
- 승인된 회원의 커뮤니티 글쓰기와 교육 자료 본문 등록
- 데스크톱·태블릿·모바일 반응형 스타일, 키보드 포커스, 접근 가능한 모달

운영진 화면 미리보기는 `http://127.0.0.1:4310/#/admin-preview`입니다. 예시 데이터만 사용하고 변경을 저장하지 않습니다. 실제 연결 설정이 있으면 이 미리보기는 제공하지 않습니다.

## 인증 연결 범위

현재 공개 설정 `dist/config.js`는 비어 있으며 Supabase 연결은 끊겨 있습니다. 따라서 실제 회원 데이터나 비공개 콘텐츠가 없고, 가입 미리보기 입력은 전송하거나 저장하지 않습니다. 구글·카카오 로그인 버튼은 연결 전 비활성 상태입니다.

`membership-schema.sql`에 서버 권한 규칙을 구현했습니다. 인증된 이메일이 있는 비익명 계정만 신청할 수 있으며 최초 상태는 `pending`입니다. `approved` 회원과 운영진만 회원 글·교육 자료를 읽거나 작성할 수 있습니다. `rejected`와 `suspended`는 회원 활동을 할 수 없습니다. 운영진은 비공개 테이블에 등록하며 사용자가 수정 가능한 계정 프로필에 권한을 저장하지 않습니다. 본인 신청 조회와 운영진 검토만 허용하고, 검토 이력은 별도 기록합니다.

회원 접수는 데이터베이스의 비공개 설정에서 기본적으로 닫혀 있습니다. 브라우저 설정을 임의로 바꿔도 접수를 열 수 없습니다. 승인 상태와 신청자 ID 위조, 운영자 권한 상승을 데이터베이스에서 차단합니다.

아직 위 SQL을 원격 데이터베이스에 적용하지 않았습니다. Supabase 연결 후 대상 프로젝트를 확인하고 마이그레이션으로 적용해야 합니다. 실제 OAuth 연결과 원격 승인 흐름은 아직 검증하지 않았습니다.

실제 접수에 앞서 개인정보 처리 안내, 교사 확인 방법, 승인 담당자와 운영 정책을 확정해야 합니다.

연결 순서:

1. Supabase 플러그인 계정을 연결하고 BioSEM용 프로젝트를 확인합니다.
2. 스키마 변경안을 검토·적용하고 데이터베이스 보안 점검을 실행합니다.
3. 구글·카카오 제공자를 설정하고 사이트 복귀 주소를 허용합니다. 이메일이 확인된 계정으로만 신청하도록 준비되어 있으므로 카카오 이메일 동의·확인 설정도 검증합니다.
4. 운영자가 실제 로그인한 뒤 인증 계정 ID를 확인하여 `biosem_private.admins`에 등록합니다. 이메일 문자열만 브라우저에서 비교하여 운영자 권한을 부여하면 안 됩니다.
5. `dist/config.js`에는 프로젝트 URL과 `sb_publishable_` 공개키만 넣습니다. 비밀키는 브라우저에 넣지 않습니다. 활성 제공자와 개인정보 안내 주소를 설정합니다.
6. 접수 준비를 마치면 서버의 `biosem_private.settings.accepting_applications`와 클라이언트의 접수 표시 설정을 켭니다.
7. 실제 계정으로 신청 → 운영진 검토 → 승인 → 글쓰기 → 정지를 검증합니다.

현재 자료 공유는 본문 글 등록 방식이며 파일 업로드는 포함하지 않습니다.

## 콘텐츠

활동 기록 3개는 예시라고 표시했습니다. 구성원, 기관, 일정, 연혁은 임의로 만들지 않았습니다. 갤러리에는 공개 라이선스 SEM 사진 3개를 사용하며, 이미지별 원본과 라이선스를 표시했습니다.

## 검증 및 게시 상태

스크립트 문법, 로컬 HTTP 응답, 이미지 파일, 회원 입력값 처리 및 비동기 응답 무효화를 확인했습니다. 실제 PostgreSQL을 WebAssembly로 실행하는 PGlite 0.5.8에서 서버 권한 검사 30개가 통과했습니다. 승인 위조·타인 조회·정지 후 접근·접수 중단·100명 초과 페이지 이동 등을 검사했으며 별도 코드 리뷰를 마쳤습니다. 이는 실제 Supabase 로그인 연결 시험과는 구분됩니다.

현재 환경에 사용 가능한 브라우저 연결이 없고 브라우저 실행 권한이 제한되어 실제 렌더링과 모바일 시각 검증은 미완료입니다.

검사 실행: `node membership-core.test.mjs`, `node membership-security.test.mjs`. 후자는 현재 `.sites-runtime/pglite/package/dist`에 준비된 PGlite 0.5.8을 사용합니다. `.sites-runtime`은 개발용이며 배포에 포함하지 않습니다.

브라우저 인증 라이브러리는 `@supabase/supabase-js` 2.117.2의 공식 UMD 배포본을 고정해 로컬 파일로 포함했습니다. 라이선스는 `dist/SUPABASE-LICENSE.txt`에 있습니다.

Sites 프로젝트 ID는 `.openai/hosting.json`에 보관되어 있습니다. 게시 준비 도구 실행이 실패하여 아직 온라인으로 게시하지 않았습니다. 이어서 작업할 때 새 사이트를 만들지 말고 기존 ID를 사용해야 합니다.
